## P0-1：Agent 原生接入

范围：Codex lifecycle hooks 与 Claude Code hooks 转换为稳定 `v1` AgentEvent；提供安装/校验命令、幂等、心跳、超时与审批前置判定。

不在范围：屏幕录制、默认上传全部 Prompt/源码/终端输出、替代 Agent 本身的权限模型。

验收：

1. Codex `PreToolUse/PermissionRequest/PostToolUse/Stop` 和 Claude `PreToolUse/PostToolUse/Stop` 可生成 Run/Action/Completion。
2. 同一幂等键相同负载返回 duplicate，不同负载返回 409。
3. 高风险动作在执行前返回 `allow/deny/ask`；超时默认 fail-closed，只读低风险动作可配 fail-open。
4. 超过心跳窗口的 Run 自动变为 `timed_out`，并记录原因。
5. 服务凭据不使用人类长期 JWT，可撤销、只存哈希。

## P0-2：统一模型网关与 FinOps

范围：OpenAI-compatible 单端点，路由目录、供应商密钥引用、超时、有界重试、熔断/降级、硬预算、Token/延迟/成本归因。

不在范围：自建模型推理、训练平台、原始 Prompt 分析仓、代替供应商账单。

验收：

1. 业务只配置模型别名，不直接持有供应商 Key。
2. 主路由超时/429/5xx 时按优先级切换；非幂等请求不无限重试。
3. 硬预算超限在上游调用前拦截；记录 route/outcome/latency/tokens/cost，不记录完整内容。
4. 模型成本、审批工时、返工和事故成本可分类记账；所有 ROI 带样本和基线。
5. 成本与供应商账单的月度误差阈值由 FinOps 签字确定，默认目标 ≤ 2%。

## P0-3：PR 证据自动化

范围：在 PR 创建/同步及 CI 完成后，自动拉取文件列表，与 head SHA 绑定，幂等重评并回写 Check。

验收：

1. PR `opened/synchronize/reopened` 与完成的 check/workflow 自动触发，无需点“运行最新策略”。
2. 证据包含 SHA、文件路径、CI/安全结论、覆盖率、来源和成本；敏感文件规则可版本化。
3. 乱序的旧 SHA 事件不得覆盖新决策；缺失/异常证据进入 review/block，不默认 allow。
4. 外部 API 超时进入 Outbox 重试，最终死信可见、可重放。

## P0-4：受控 Auto-merge

范围：仓库级 opt-in，仅对同一 head SHA 的最新 allow 决策发起合并，依然服从 GitHub 规则。

验收：

1. 默认关闭；仅 Owner/Admin 可启用，配置变更进审计。
2. 必须同时满足：PR open、最新策略 allow、无待审批、required checks 成功、SHA 未变、无冲突。
3. 任一前置条件不满足均不合并，回写稳定原因码；不得使用管理员权限绕过 branch protection。
4. GitHub 冲突/409、限流/429、超时和合并后响应丢失均幂等收敛。

## P0-5：Git 源码治理与 CI/CD

范围：独立远程、分支保护、CODEOWNERS、required CI、签名镜像、staging 自动部署、production 环境审批与回滚。

验收：

1. main 禁止直接 push，至少一名审核，所有 required checks 成功，CODEOWNERS 覆盖安全/迁移/部署。
2. PR 运行后端、前端、PostgreSQL 迁移、E2E、依赖/密钥/镜像扫描和清单校验。
3. main 只部署 staging；production 仅从不可变 digest 发布，需 GitHub Environment 审批。
4. 部署后运行 smoke/health/migration 验证；失败自动回滚并保留证据。

## 统一降级与异常策略

| 异常 | 默认策略 | 用户可见结果 |
|---|---|---|
| 输入格式/版本不支持 | 拒绝，不落业务证据 | 400/422 + 稳定错误码 |
| 幂等键冲突 | 保留首条，拒绝覆盖 | 409 `EVIDENCE_CONFLICT` |
| 旧 SHA /乱序事件 | 记录但不更新当前决策 | `stale_ignored` 审计 |
| Agent 审批超时 | 高风险 fail-closed 并升级 | `timed_out/blocked` |
| GitHub/Model 限流 | 遵守 Retry-After，抖动退避 | 队列状态、下次重试时间 |
| Model 超时/5xx | 有界重试后路由降级 | 实际 route 和 degraded 标记 |
| 策略服务不可用 | 变更/高风险动作 fail-closed | `POLICY_UNAVAILABLE` |
| 审计仓写入失败 | 不执行外部副作用 | 请求失败 + 告警 |
| 重试耗尽 | 死信，需有权人重放 | 死信看板/审计 |

## 主要风险

| 风险 | 控制 | 验收证据 |
|---|---|---|
| 把不完整证据当成 allow | 缺失非通过、SHA 绑定、策略版本 | 缺失/乱序/伪造用例 |
| Agent 绕过审批 | 执行前 Hook、服务身份、最小权限 | 高风险命令端到端拦截 |
| 自动合并越权 | 默认关闭、GitHub 规则为最终门禁 | 冲突/失败 CI/未审批不合并 |
| 供应商成本失控 | 上游前硬预算、循环检测、对账 | 超额拦截与账单误差报告 |
| 内容/密钥泄漏 | 最小采集、密钥引用、日志脱敏 | Secret 扫描与日志抽检 |
| 单人维护无生产责任人 | RACI、CODEOWNERS、环境签字 | 上线门禁人员完整 |

## 终止条件

五个 P0 模块的代码通过不等于上线批准。任一 `docs/03-最终交付与验收.md` P0 门禁未附证据时，结论仍为 NO-GO。

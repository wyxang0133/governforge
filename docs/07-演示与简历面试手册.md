# 演示、简历与面试手册

## 五分钟演示

1. 登录后打开治理看板，说明 GovernForge 是多 Agent 的企业控制平面。
2. 通过 GitHub Webhook 产生仓库和 PR，展示来源证据、Scorecard 和策略决策。
3. 创建严格策略或预算，让高风险 PR 进入审批/阻断并回写 GitHub Check。
4. 打开企业知识助手，导入一份 Markdown/PDF，说明服务端解析和分块索引。
5. 提问“认证和数据库迁移是否能由 AI 直接修改”，展示分类、引用、置信度和用量成本。
6. 提交有帮助/无帮助反馈，再转人工专家，最后到审计页按 Trace ID 还原链路。

## 面试拆解

### 为什么不是再做一个 Coding Agent？

Codex、Claude Code、Cursor 已解决执行层。企业缺的是跨工具的证据标准、合并门禁、成本归因、权限和审计，因此 GovernForge 选择控制平面；知识 Agent 用来展示 Agent 工作流与 RAG，但其工具权限受控。

### Agent 在哪里？

知识请求经过分类、检索、安全决策、模型/降级工具选择、引用、反馈与升级，是一个有限状态的受控 Agent。自主性被限制在可审计工具内，避免任意执行带来的越权风险。

### 为什么要 Outbox？

策略结果与 GitHub Check 不能分布式原子提交。业务事务同时写 Outbox，Worker 至少一次投递，外部调用使用幂等键，失败指数退避并进入死信，保证可恢复和可审计。

### 为什么不直接把文档全塞给模型？

上下文长度、成本、权限和幻觉不可控。先分块检索缩小证据，再生成；模型不可用时确定性降级；所有回答保留引用、成本和 Trace。

### 当前检索为什么不是向量库？

RC 优先零外部依赖和可重复演示。领域层已经分离 Article/Chunk/Retrieval，后续可替换 pgvector；是否迁移由语料规模、Recall@K、延迟和成本数据决定，而不是为了堆技术名词。

### 多租户如何保证？

身份 Token、请求 Workspace、查询条件和表字段共同约束；Webhook 以受信 Installation 映射 Workspace，不接受不可信租户头；生产还应补数据库 RLS 和租户逃逸安全测试。

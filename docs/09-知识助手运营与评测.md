# 企业知识助手运营与评测

## 内容生命周期

1. 知识管理员导入 PDF/Markdown/文本或手工创建条目。
2. 系统提取文本、分块并记录来源、版本、创建人和审计事件。
3. 业务 Owner 负责真实性、敏感等级、适用范围和过期时间；当前 RC 由外部流程审批。
4. 修改产生新版本号并重建分块；归档后不再参与检索。
5. 对话反馈与人工升级进入运营队列，形成 FAQ 和知识缺口回补。

## 模型配置

默认 `KNOWLEDGE_LLM_ENABLED=false`，使用零成本 extractive RAG。接入企业 Gateway 时配置：

- `KNOWLEDGE_LLM_BASE_URL`、`KNOWLEDGE_LLM_API_KEY`、`KNOWLEDGE_LLM_MODEL`
- `KNOWLEDGE_INPUT_COST_PER_MILLION`、`KNOWLEDGE_OUTPUT_COST_PER_MILLION`

密钥必须通过 Secret Manager 注入。模型超时、HTTP 失败或响应不合法会降级，并在审计 payload 的 `fallback_reason` 中记录原因。

## 离线评测集

每个业务域至少准备：标准问题、允许的同义问法、期望分类、支持文档、关键事实、应拒答条件和风险等级。建议门禁：

- Retrieval Recall@5 ≥ 90%
- 引用支持率 ≥ 95%
- 高风险错误回答率 = 0
- 无证据问题拒答率 ≥ 95%
- P95 延迟与单问成本不超过业务约定

阈值必须由真实评测结果和业务 Owner 批准，不应写死为营销数字。

## 在线运营指标

- 查询量、分类分布、grounded/no-answer/blocked 比例。
- helpful/unhelpful、人工升级率、队列积压和解决 SLA。
- provider/model/token/cost、超时/降级率。
- 无命中高频问题、低反馈文档、长期未更新文档。

## 当前规模边界

当前 PostgreSQL 分块混合检索适合项目演示和中小语料。达到以下任一条件再引入 pgvector/专用检索服务：语料或查询延迟超出 SLO、Recall@K 不达标、需要语义召回/多模态、或文档 ACL 过滤成为性能瓶颈。

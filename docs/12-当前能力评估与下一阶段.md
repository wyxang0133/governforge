# 当前能力评估与下一阶段

更新日期：2026-07-19

## 发布判定

当前状态是“可演示的 Release Candidate”，不是“Production Approved”。真实 GitHub App、Webhook、CI 证据、策略阻断、审批、审计和 Check 回写已经验证；真实 Agent 原生连接器、统一模型网关、自动策略触发、受控合并和目标集群 CD 尚未完成。

## 能力矩阵

| 能力 | 当前状态 | 结论 |
|---|---|---|
| GitHub App | 已验证 | 真实 Installation、Webhook、仓库同步和 Check 回写可用 |
| PR 治理 | 部分自动化 | 证据、策略、审批和审计可用；CI 完成后仍需自动触发评估并拉取完整 diff |
| Agent 行为治理 | 适配层 | AgentRun/AgentAction API 与通用 CLI 可用；Codex、Claude Code、Cursor 原生安装器和真实事件验证未完成 |
| 模型统一接入 | 事件账本 | 支持 OpenAI-compatible 单模型配置和 Gateway Usage 上报；尚无统一路由、虚拟 Key、限流、熔断和密钥管理 |
| FinOps | 基础可用 | Token、成本、预算和归因可用；缺合同价、缓存折扣、多币种和供应商账单对账 |
| LLM/Agent 可观测性 | 基础可用 | Trace、审计、Prometheus/OTLP 基础存在；缺完整嵌套 Trace、Prompt/工具调用视图和在线评估 |
| 自动合并 | 未实现 | 平台只回写 Check，不直接合并 PR；应在分支保护、审批和全部必需检查通过后使用 GitHub Auto-merge/merge queue |
| CI | 模板完整 | 平台仓库包含后端、前端、PostgreSQL、E2E、镜像与清单检查；当前目录尚未发布为远程 GitHub 仓库，因此平台 CI 未实际运行 |
| CD | 未实现 | tag 镜像发布工作流存在；未部署到真实 staging/production 集群，也没有环境审批、渐进发布和自动回滚 |
| 企业知识助手 | 演示可用 | 分类、检索、引用、拒答、反馈和人工升级存在；缺真实文档连接器、ACL、向量规模和金标评测 |

## 下一阶段 P0

1. 提供 Codex Plugin/Hook 与 Claude Code HTTP Hook 安装器，把 PreToolUse、PostToolUse、Stop、审批结果映射为标准 AgentAction，并完成端到端阻断验证。
2. 接入 LiteLLM 类统一模型网关：模型目录、供应商路由、虚拟 Key、团队限额、重试/熔断、成本回传和密钥引用；DevPilot 保留治理与审计控制面，不重复实现推理代理细节。
3. 在 GitHub check/workflow 完成事件后自动拉取 PR files/diff、安全扫描和覆盖率证据，幂等执行策略并更新同一个 Check Run。
4. 增加受控 Auto-merge：仅在策略 allow、所需审批完成、分支保护与全部 required checks 通过后启用 GitHub Auto-merge；禁止绕过 GitHub 规则直接 merge。
5. 将 DevPilot 发布到独立 GitHub 仓库，启用 branch protection、CODEOWNERS、CI required checks；为 staging 增加 OIDC、environment approval、部署验证与回滚工作流。

## 下一阶段 P1

- 接入 Langfuse 类 LLM/Agent Trace 与评测能力，保留 DevPilot 的跨 Agent、PR、审批和责任归因视图。
- 将自定义策略引擎演进为可插拔 PDP，评估 OPA/Rego，保留现有企业策略模板和版本审计。
- 增加真实文档源、ACL 透传、增量同步、删除/留存和检索评测集。
- 补齐模型供应商账单对账、异常用量检测、缓存折扣和多币种成本归因。

# 产品定义与目标架构

## 产品定位

DevPilot 面向 50–500 人研发组织的平台工程、研发效能、安全、FinOps 和内部知识运营团队。核心价值不是替代 Coding Agent，而是让企业能安全、可控、可衡量地采用多个 Agent 和大模型。

核心业务问题：

- AI 生成或辅助的变更是否有可信来源、测试与安全证据？
- 高风险变更是否应用了正确策略并由正确角色审批？
- 模型成本能否归因到 Workspace、团队、仓库和业务场景？
- 员工能否从企业制度中快速得到有引用、可复核的答案？
- 失败、拒答、人工升级和外部副作用能否被完整追踪？

## 逻辑架构

```text
                         ┌──────────────── DevPilot Control Plane ────────────────┐
GitHub App/Webhook ─────>│ Integration API → Evidence/Scorecard → Policy/Approval │─> GitHub Check
CI Evidence ────────────>│                         │                    │           │
LLM Gateway Usage ──────>│                         └→ Budget/Cost       └→ Outbox  │
                         │                                                     │   │
PDF/MD/TXT ─────────────>│ Parse → Chunk Index → Hybrid Retrieve → Guardrail    │   │
User Question ──────────>│ Classify ──────────────────────────────> LLM/Fallback │─> Citation
                         │                                      └→ Feedback/Escalation
                         │                                                         │
                         │ PostgreSQL + Append-only Audit + Trace + Metrics/OTLP   │
                         └─────────────────────────────────────────────────────────┘
```

## Agent 属性

知识助手具备一个受控 Agent 工作流：意图分类、知识检索、安全决策、工具选择（模型或确定性降级）、结果引用、用户反馈和人工升级。它刻意不开放任意代码执行和任意外部工具，适合企业高风险场景的“有限自主、全程可审计”原则。

## 数据边界

治理域默认不采集完整 Prompt、源码和终端内容；知识域只保存管理员主动导入的文档、对话和反馈。所有业务表带 `workspace_id`。生产必须定义文档分类、留存、删除、Legal Hold 和知识管理员责任。

## 扩展点

- SCM：GitLab/Bitbucket 适配器提交规范化证据。
- Model：任何实现 `/chat/completions` 的 OpenAI-compatible Gateway。
- Retrieval：当前 PostgreSQL 分块混合检索可替换为 pgvector/Qdrant，API 与审计模型不变。
- Workflow：人工升级可通过 Outbox 对接 Jira、ServiceNow、飞书或企业工单。

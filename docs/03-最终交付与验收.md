## 当前已落地的 GitHub 权限基线

仓库 `wyxang0133/governforge` 已切换为公开，原因是 GitHub Free 对私有仓库的 branch protection 返回 403；公开仓库可在 Free 计划启用保护。`main` 当前规则为：至少 1 个 PR 审批、必须经过 CODEOWNERS、必须通过 `backend`、`frontend`、`postgres-integration`、`browser-e2e`、`images`、`manifests`，要求线性历史、禁止 force-push/删除，并要求最近一次 push 由其他审阅者批准。

公开仓库只能放置脱敏源码和示例配置；真实私钥、Webhook Secret、OIDC Secret、模型 Key、生产数据必须通过 GitHub Secrets/Environment 或外部密钥系统注入。若未来需要私有源码，应升级 GitHub Pro/Team/Enterprise 后迁移回私有并重新回读保护规则。

## 未完成实施的统一交付标准

“代码存在”不计为完成。每个项目必须同时具备真实目标环境执行记录、commit 或镜像 digest、Trace/审计链接、异常反例和负责人签字。以下任一项缺失，交付状态保持 `进行中` 或 `阻断`：

- Agent：Codex 与 Claude Code 各完成一次真实低风险、高风险和断网恢复任务；高风险零误放行。
- Gateway：至少两个真实上游，完成 429/5xx/超时降级、并发预算竞争、密钥轮换和月度账单对账。
- PR：真实仓库完成 opened/synchronize/CI 完成/旧 SHA 乱序/Check 重试；allow、review、block 均有 API 响应。
- Auto-merge：只允许同 SHA、allow、无待审批、required checks 全绿的正例；失败 CI、冲突、待审批和 SHA 变化必须证明不合并。
- CD：staging 真实部署、健康检查、迁移、回滚各至少一次；production 使用不可变 digest 和 Environment 审批。
- 安全与数据：Secret 扫描、OIDC/SCIM 撤销、审计不可丢失、备份恢复、RPO/RTO 和知识助手 ACL/DLP 由对应 Owner 签字。

## 必须演练的异常场景

- 违法 schema、重复事件、同 key 不同 payload、旧 SHA 晚到。
- GitHub 401/403/409/422/429/5xx，Webhook 重放，Check 响应丢失。
- Model 429/超时/5xx，主备都失败，流式输出中断，预算在并发请求中耗尽。
- Agent 失联、审批超时、审批人离职、发起人尝试自审批。
- PostgreSQL 短断、Outbox 重试耗尽、Worker 双活、审计写入失败。
- 部署健康检查失败、迁移向后不兼容、回滚镜像无法读新 schema。

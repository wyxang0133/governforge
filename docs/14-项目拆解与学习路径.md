# GovernForge 项目拆解与学习路径

更新日期：2026-07-21

目标不是背代码，而是让你能独立说明业务问题、架构取舍、关键实现、异常边界和上线方法，并能现场修改一个模块。

## 一、并行推进方式

| 工作流 | 是否可并行 | 负责人 | 依赖 |
|---|---|---|---|
| 后端策略、Agent、模型网关代码 | 可以 | Codex 主导，你参与审查 | 无外部依赖 |
| 测试、静态检查、CI 修复 | 可以 | Codex 主导 | 代码变更 |
| 前端页面和数据可视化 | 可以 | Codex 主导，你验收视觉和流程 | 后端 API 合同 |
| 文档、架构图、面试材料 | 可以 | Codex 起草，你用自己的话复述 | 模块实现基本稳定 |
| GitHub PR 正反例 | 部分并行 | 你执行真实仓库操作，Codex 分析证据 | GitHub App、Webhook、分支保护 |
| Codex/Claude Code Hook | 部分并行 | 你在本机执行，Codex 修复适配问题 | Agent Token、运行环境 |
| 真实模型故障转移和账单 | 阻塞于外部权限 | 你提供供应商与价格，Codex 验证 | 两个真实 API Key |
| staging CD、备份恢复、RPO/RTO | 阻塞于外部环境 | 你提供集群和 Owner，Codex 修复流水线 | kubeconfig、环境审批 |
| OIDC/SCIM、生产签字 | 阻塞于外部责任人 | 你组织 IAM/Security/SRE/FinOps | 企业身份和责任人 |

结论：代码、测试、文档、CI/CD 可以继续做；真实外部验收只能在你提供环境后完成，但两条线不需要互相等待。

## 二、你需要真正掌握的六层知识

### 1. 业务层

你要能回答：企业为什么不能直接让 Codex/Claude Code 改完就合并？

核心答案：AI Coding 带来安全、质量、成本、合规和责任归因问题，GovernForge 是控制面，把 Agent、GitHub、CI、模型调用和人工审批连成可评分、可审计的交付链路。

### 2. 数据合同层

掌握 `AgentEvent v1`、Webhook、CI Evidence、Model Usage 的字段、版本、幂等键、Trace ID、head SHA 和冲突语义。

练习：你亲自解释为什么“同一幂等键不同 payload 必须返回 409”，以及为什么旧 SHA 的晚到事件不能覆盖新决策。

### 3. 策略与安全层

掌握 Scorecard、Policy Gate、allow/review/block、敏感文件、成本预算、证据完整性和 fail-closed。

练习：修改策略阈值，让一个 PR 从 allow 变成 review，再恢复证据让它重新评估。

### 4. Agent 工程层

掌握 Run、Action、Approval、Evaluation、Hook、心跳、超时、自审批禁止和机器凭据撤销。

练习：亲自跑一次低风险读取、一次高风险文件写入、一次审批超时，并在审计页面追踪完整 Trace。

### 5. 平台工程层

掌握 PostgreSQL/Alembic、Outbox、Worker、GitHub App Installation Token、Check 回写、模型网关、预算和成本账本。

练习：让主模型返回 503，观察备用路由、degraded 标志、成本事件和审计事件。

### 6. 生产工程层

掌握 branch protection、CODEOWNERS、required checks、不可变镜像、Environment 审批、Kubernetes rollout/rollback、备份和 SLO。

练习：故意让 staging rollout 失败，确认工作负载回滚，并说明为什么数据库迁移不能盲目自动回滚。

## 三、每个模块的带学流程

每次学习按固定顺序进行：

1. 先讲业务问题和真实企业场景。
2. 画出请求、数据、策略、审计和异常链路。
3. 阅读对应 API、模型、核心服务和测试。
4. 你先用自己的话解释设计。
5. 你亲自运行一个正例和一个反例。
6. 你修改一个小需求，我带你跑测试和审查。
7. 最后整理成简历表达和面试追问。

## 四、建议学习顺序

1. 先学 PR 治理闭环：Webhook → Evidence → Scorecard → Policy → Check。
2. 再学 Agent 行为接入：Run → Action → Approval → Evaluation。
3. 再学 Model Gateway：路由、重试、熔断、预算、TCO。
4. 再学 Outbox、审计、Trace 和多租户隔离。
5. 最后学 GitHub App、CI/CD、Kubernetes 和生产门禁。

## 五、最终你要能独立完成的面试演示

你应能在 10 分钟内完成：创建一个带 AI 来源的 PR；展示 CI 和安全证据；解释策略为何 review/block；发起高风险 Agent Action 并审批；展示 Check、Audit Trace、模型成本和最终受控合并。

一句话表达：

> 我构建的是企业 AI Coding 与 Agent 工程治理控制面，而不是另一个 Coding Agent。它统一接入 Agent 行为、GitHub PR、CI 和模型调用，通过证据、策略、人工审批、成本账本和审计追踪，控制 AI 代码交付风险。

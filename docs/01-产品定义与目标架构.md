# GovernForge 产品定义与责任边界

更新日期：2026-07-20

## 一句话定位

GovernForge 是企业 AI Agent 工程治理控制面：把 Coding Agent、模型调用、SCM/CI 与人工审批连成可策略化、可归因、可追踪、可回滚的交付链路。它不是另一个 Coding Agent，也不是只面向高管的报表工具。

## 目标用户

| 角色 | 日常目标 | 主要界面 |
|---|---|---|
| 平台工程 / AgentOps | 接入 Agent、SCM、CI 和模型，维护可用性 | 连接器、Agent 运行、模型路由、运行状态 |
| 研发负责人 | 提升交付速度与质量，处理例外 | 交付看板、变更门禁、审批 |
| 安全 / 合规 | 管理高风险操作、数据边界与审计证据 | 策略、审批、审计、风险事件 |
| FinOps / 业务 Owner | 管理预算、单位成本与 ROI | 模型与成本、预算、对账 |
| 开发者 | 知道变更为何被放行或拦截，快速补证 | PR 证据、Agent 轨迹、策略理由 |
| CTO / 研发高管 | 了解投入、风险、效率和责任归属 | 管理驾驶舱（只读为主） |

## 参与者与 RACI

| 链路 | 发起 R | 处理 R | 最终负责 A | 审核 / 咨询 C | 被知会 I |
|---|---|---|---|---|---|
| Agent 编码任务 | 开发者 / 任务系统 | Coding Agent | 仓库 Owner | 安全（高风险时） | 研发负责人 |
| PR 评估 | GitHub Webhook / CI | GovernForge 策略引擎 | 仓库 Owner | Security / CODEOWNERS | PR 作者 |
| 高风险操作 | Agent | 审批队列 | Security 或 Owner | Platform | 任务发起人 |
| 受控合并 | 策略 allow | GitHub / Merge Queue | 仓库 Owner | CODEOWNERS、CI | PR 参与者 |
| 模型路由 | 业务应用 / Agent | Model Gateway | AI Platform Owner | Security、FinOps | 业务 Owner |
| 预算例外 | 业务 Owner | FinOps | FinOps Owner | 研发负责人 | Platform |

审批人不得审批自己发起的 critical 操作；紧急 break-glass 必须双人复核、设置过期时间并产生不可变审计事件。

## 核心业务闭环

```text
需求/任务 → Agent Run → Action 预检 → 执行/审批 → 测试与 PR
       → GitHub/CI/Model 证据 → Scorecard → Policy Gate
       → allow/review/block → 人工决策 → Check/受控合并
       → Audit/Trace/Cost/Outcome → 复盘与策略迭代
```

## 数据来源与证据等级

| 来源 | 数据 | 可信等级 | 失效处理 |
|---|---|---|---|
| GitHub App | PR、文件列表、Check、合并状态 | 高，签名 Webhook + Installation 身份 | 拒绝伪签名；重放幂等；限流后退避 |
| CI | 测试、覆盖率、SAST/依赖/密钥扫描 | 高，与 head SHA 绑定 | 缺失不视为通过；过期证据不复用 |
| Agent Hook | 计划、命令、文件、工具、结果 | 中高，短期服务凭据 + 幂等键 | 冲突返回 409；超时标记 timed_out |
| Model Gateway | provider/model/token/延迟/成本 | 高，由统一网关计量 | 路由故障按策略降级；不伪造用量 |
| 人工审批 | 决策、理由、角色、时间 | 高，OIDC 身份 + 职责分离 | 超时升级；禁止静默放行 |
| 人工录入 | 知识、单价、例外理由 | 中，需 Owner 与版本 | 校验、复核、过期提醒 |

所有外部事件使用 `schema_version=v1`、`event_id`、`occurred_at`、`workspace_id`、`trace_id`和业务幂等键。同一幂等键但负载不同视为数据冲突，不得覆盖原证据。

## 边界

### 平台负责

- 规范化外部事件，评估 Agent 与 PR，执行预算/策略/审批门禁。
- 提供模型路由、超时、重试、熔断、成本计量和供应商降级。
- 保存最小必要的证据、决策、身份、Trace 和成本。
- 为 GitHub 回写 Check；仅对明确启用的仓库执行受控合并。

### 平台不负责

- 不替代 Codex、Claude Code、Cursor 等 Agent 执行编码。
- 不承诺 LLM 输出一定正确；不以模型自评代替确定性检查。
- 不绕过 GitHub branch protection、CODEOWNERS 或 required checks。
- 不默认保存完整 Prompt、源码 diff、终端输出和模型回答。
- 不宣称模板已等于目标企业的合规认证、容灾能力或生产批准。

## 成本口径

`TCO = 模型/API + 计算/存储/流量 + 审批人工 + 返工 + 错误/事故 + 机会成本`。

- 审批人工成本 = 审批时长 × 角色小时费率。
- 返工成本 = 修复时长 × 工程师费率 + 重跑 CI/Agent 成本。
- 错误成本 = 事故处理工时 + 停机/违约/数据风险的审批估值。
- ROI 必须同时展示基线、实际、样本数和可信度，不用缺失数据推导“节省”。

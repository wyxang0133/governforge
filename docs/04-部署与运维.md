# 生产部署与运维手册

## 1. 配置与密钥

生产密钥必须由 Secrets Manager/Vault/External Secrets 注入，禁止进入 Git、镜像或 ConfigMap。

- 数据库：`DATABASE_URL`（Kubernetes）或 `POSTGRES_PASSWORD`（本地 Compose）。
- 身份：`JWT_SECRET_KEY`、OIDC Issuer/Client/Secret/Redirect URI、SCIM Bearer Token。
- GitHub：Webhook Secret、App ID、PEM 私钥；仅兼容场景使用静态 Checks Token。
- 网络与观测：`CORS_ORIGINS`、OTLP Endpoint、日志级别/JSON、采样率。
- 知识模型：`KNOWLEDGE_LLM_ENABLED`、Gateway URL/API Key/Model、输入输出合同单价；默认关闭。

生产强制：`ENVIRONMENT=production`、`ALLOW_SELF_REGISTRATION=false`、`ALLOW_LOCAL_AUTH=false`、`LOG_JSON=true`。先在目标 IdP 验证至少两个管理员和一个受控 break-glass 账号，再关闭本地认证。

## 2. Kubernetes 发布

1. 将 `deploy/kubernetes/kustomization.yaml` 中镜像替换为 Release workflow 生成并经 Cosign 验证的不可变 digest。
2. 从 `external-secret.example.yaml` 创建目标平台 ExternalSecret，或以同等方式生成 `devpilot-secrets`。
3. 把 ConfigMap 的域名、OIDC 和 Workspace 值改为目标环境值。
4. 渲染并审查：`kubectl kustomize deploy/kubernetes`。
5. 先运行迁移 Job；成功后再滚动 Backend、Worker、Frontend。
6. 检查 `/livez`、`/health`、`/metrics`、Worker metrics 和登录页，再放量 Ingress。

清单包含 non-root、只读根文件系统、capabilities drop、seccomp、资源限制、HPA、PDB、默认拒绝 NetworkPolicy 与 TLS Ingress。NetworkPolicy 中公共 443 等出站规则是跨 CNI 的基线，生产应按目标 CNI 收紧为 IdP、GitHub、OTLP 和数据库的明确目标。

## 3. 数据迁移与回滚

- 发布前备份；迁移由单独 Job 执行，应用容器不得并发自动迁移。
- 先在同版本 PostgreSQL 的恢复副本执行 `alembic upgrade head` 和回滚演练。
- Schema 向前兼容时回滚应用镜像；破坏性迁移必须 Expand/Migrate/Contract 分发布完成。
- 当前迁移头为 `20260719_0010`，`0009` 回填旧知识分块，`0010` 增加 Agent Run/Action/Approval/Evaluation。CI 必须验证空库升级和从上一版本升级。

## 4. 监控、SLO 与处置

建议首期 SLO：月可用性 99.9%，治理 API p95 < 800ms，Webhook 5xx < 1%，Outbox 99% 在 5 分钟内完成。`deploy/observability/prometheus-rules.yml` 提供错误率、p95、Webhook 失败、Worker 停滞和死信告警基线。

- API `/metrics`；Worker `:9100/metrics`；Trace 通过 OTLP 导出。
- 所有请求保留 Trace ID，JSON 日志禁止写入 Token、Prompt、源码和 Cookie。
- 知识指标包括查询 outcome、用户反馈和专家升级；同时从 UsageEvent 观察模型成本与降级率。
- 死信先定位权限/限流/网络原因，修复后在系统页受控重放；禁止直接改审计记录。
- 告警必须路由到有 Owner 的值班渠道，并为每个 P0/P1 告警附 Runbook。

## 5. 备份与恢复

示例 CronJob 每日 `pg_dump` 到 PVC 并保留 14 天，只是开发基线。生产优先使用托管数据库 PITR，并将加密备份复制到独立账号/区域的对象存储。至少季度恢复演练：新建隔离库、恢复、迁移、启动应用、核对租户/审计/Outbox/核心计数，记录实际 RPO/RTO。

## 6. 发布、回滚与安全

- Tag 发布构建 SBOM 和 provenance，并对镜像 digest 进行 Sigstore keyless 签名。
- CI 阻断高危/严重依赖、镜像、Secret 和配置风险；Dependabot 每周提出更新。
- 灰度一个内部 Workspace，观察错误率、p95、Webhook、预算和死信后逐步放量。
- 回滚应用必须使用上一个已签名 digest；数据库按已演练兼容策略处理，禁止临时手工改表。
